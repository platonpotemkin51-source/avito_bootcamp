# Как читать код решения

Это дополнение к solution.ipynb. Здесь разобраны конструкции, которые могут выглядеть непривычно. Код исследования целиком остаётся в ноутбуке.

В начале каждой функции теперь есть короткая документация в тройных кавычках: что функция делает, что принимает и что возвращает. Например, `help(make_features)` в отдельной ячейке покажет описание расчёта признаков. Строки с `#` объясняют отдельные действия и не выполняются Python.

Промежуточные переменные вроде `positive_scores`, `local_word_order` и `location_multiplier` позволяют посмотреть результат каждого шага. Массивы NumPy и готовые алгоритмы scikit-learn сохранены: они нужны для обработки большого корпуса. Упрощение записи не меняет параметры моделей и схему эксперимента.

## 2. Одна строка и целый столбец

```python
clean_text("РЕМОНТ телевизоров!")
```

Функция получает одну строку и возвращает `"ремонт телевизоров"`.

```python
items["item_title_raw"].map(clean_text)
```

`map` вызывает ту же функцию для каждого заголовка в столбце. Не требуется создавать временный pd.Series для отдельного запроса. Проверка `pd.isna` внутри функции позволяет обработать пропуски до вызова строковых методов.

## 3. Как собираются правильные ответы

```python
train.groupby(search_columns, dropna=False)["item_id"].agg(set)
```

`groupby` собирает вместе строки с одинаковыми условиями поиска. `dropna=False` сохраняет группы с пропусками в условиях. Из каждой группы берём item_id. `agg(set)` превращает их в множество: A, B, A превращается в A, B.

Множество удобно для проверки принадлежности и пересечения. В отличие от списка, оно не содержит повторов и не задаёт порядок ответов.

```python
relevant_items.issubset(corpus_ids)
```

Вопрос: «Каждый известный правильный ответ есть в корпусе?» Для `{A, B}` и корпуса `{A, B, C}` ответ True. Для `{A, D}` ответ False. Во втором случае локальная проверка исключает весь запрос, чтобы не требовать от поиска найти отсутствующее объявление.

## 4. Зачем нужны три части данных

На train модель учится. На dev мы решаем, какой вариант работает лучше. На test проверяем уже принятое решение.

Если выбирать вариант по test, test перестаёт быть независимой проверкой. Если один и тот же запрос попадёт в train и test с разными объявлениями, оценка может оказаться слишком оптимистичной. Поэтому GroupShuffleSplit держит одинаковый очищенный текст в одной части.

`next(splitter.split(...))` достаёт одно разбиение. Возвращаются номера строк. `eligible.iloc[train_positions]` выбирает строки по этим номерам. Затем `sample` ограничивает число запросов для скорости, а `reset_index(drop=True)` заново нумерует строки.

## 5. Как матрицы дают оценки сходства

Допустим, есть 3 объявления и словарь из 4 слов:

```text
Матрица объявлений: 3 × 4
Вектор одного запроса: 1 × 4
```

Сравнить запрос со всеми объявлениями можно так:

```python
query_vector @ item_vectors.T
```

`.T` меняет местами строки и столбцы. Размеры умножения: `1 × 4` на `4 × 3`, результат `1 × 3`: три оценки, по одной на объявление.

В ноутбуке сразу берём 32 запроса. Для полного корпуса результат имеет размер `32 × 189212`. `.toarray()` превращает разреженный результат в обычный массив. `word_scores[number]` достаёт оценки одного запроса из пакета.

Значения — косинусные сходства нормированных TF-IDF-векторов. Они не являются вероятностями выбора. Нулевое значение означает отсутствие общих признаков в данном индексе.

## 6. Как выбираются лучшие позиции

Пусть оценки равны:

```text
позиция:  0     1     2     3
оценка:  0.2   0.0   0.8   0.4
```

```python
positions = np.flatnonzero(scores > 0)
```

Получим `[0, 2, 3]`: номера положительных оценок.

```python
order = np.argsort(-scores[positions], kind="stable")
```

Сначала `scores[positions]` даёт `[0.2, 0.8, 0.4]`. Минус превращает значения в `[-0.2, -0.8, -0.4]`. Сортировка по возрастанию отрицательных значений означает сортировку исходных оценок от большей к меньшей.

`order` равен `[1, 2, 0]`: это позиции внутри короткого массива оценок. Поэтому `positions[order]` возвращает номера исходных объявлений `[2, 3, 0]`. Срез `[:limit]` оставляет нужное количество.

`kind="stable"` сохраняет порядок при равных оценках. Это нужно для повторяемости, а не для улучшения качества.

## 7. Зачем нужны четыре списка

Поиск по словам и поиск по частям слов могут находить разные объявления. Локальные списки позволяют включить объявления нужного города даже тогда, когда глобальный список занят похожими текстами из других городов.

```python
np.concatenate([word_best, char_best, local_word_best, local_char_best])
```

Соединяет четыре массива в один. `np.unique` убирает повторы и упорядочивает номера объявлений. Получившийся порядок ещё не отражает качество: далее кандидаты получают итоговые оценки.

`positions` содержит номера строк корпуса. `item_ids[positions]` превращает их в настоящие идентификаторы. Эти два вида значений нельзя путать: в CSV нужны только item_id.

## 8. Что такое признаки пары

Для одного запроса и одного объявления получаем строку примерно такого смысла:

```text
совпадение слов = 0.6
совпадение частей слов = 0.7
совпадение города = 1
совпадение категории = 1
рейтинг = 4.8
...
```

`np.column_stack` собирает отдельные столбцы признаков в одну таблицу. Строк столько, сколько кандидатов, столбцов — 18. `astype(np.float32)` делает все значения числами одного типа и экономит память.

`np.full(count, value)` повторяет свойство запроса для каждого кандидата. Например, число слов в запросе одинаково для всех его объявлений.

Для пропусков рейтинга и других числовых свойств есть отдельные флаги. Это позволяет отличить неизвестное значение от настоящего нуля. `log1p(x)` вычисляет `log(1 + x)` и уменьшает разницу масштабов между небольшими и очень большими ценами или числами отзывов.

## 9. Как появляются метки и веса

Метка 1 означает, что этот item_id известен как выбранный по запросу. Метка 0 означает, что такого выбора в разметке нет. Это не гарантированная нерелевантность: объявление могло не попасть на экран пользователя.

Допустим, у запроса найдено 2 положительных и взято 80 остальных кандидатов. Каждому положительному до общей нормировки назначаем вес `0.5 / 2`, каждому отрицательному — `0.5 / 80`. Сумма весов каждого класса равна 0.5. Поэтому большой список отрицательных примеров не подавляет положительные только своим количеством.

`rng.choice` случайно выбирает до 80 отрицательных кандидатов без повторов. Генератор имеет фиксированный seed. Правильные объявления не добавляются в кандидаты искусственно: если поиск их не нашёл, отбор не учится на выдуманном идеальном списке.

## 10. Что именно обучается

```python
model.fit(X_train, y_train, sample_weight=sample_weights)
```

Бустинг получает признаки, метки и веса. Он строит последовательность деревьев с условиями наподобие «совпадает ли город?» и «насколько велико текстовое сходство?». Конкретные пороги и комбинации признаков определяются по обучающим данным.

```python
scores = model.predict_proba(features)[:, 1]
```

Модель возвращает оценки двух классов. `[:, 1]` берёт для всех строк столбец класса 1. По этим значениям сортируем кандидатов и выбираем 50. Из-за весов и отбора отрицательных примеров значения не следует трактовать как реальные вероятности пользовательского выбора.

Это обучаемый этап внутри нашей системы кандидатогенерации: внешний проверяющий всё равно получает только 50 item_id.

## 11. Как считается качество

```python
found = predicted_ids.intersection(relevant_items)
recall = len(found) / len(relevant_items)
```

Если правильные ответы `{A, B}`, а в выдаче `{A, C, D}`, пересечение `{A}`, Recall равен 1/2. Среднее по запросам даёт итоговую метрику. Запрос с одним ответом и запрос с несколькими ответами имеют одинаковый вес при усреднении.

Для полноты расширенного списка используем все его кандидаты вместо 50. Это показывает ограничение первого этапа. Даже идеальный отбор не восстановит объявление за пределами этого списка.

## 12. Что означает интервал разницы

На каждом запросе вычитаем Recall базового метода из Recall выбранного. Bootstrap много раз пересобирает выборку с повторениями и считает среднюю разницу. Одинаковые тексты выбираются целыми группами.

Если нижняя граница полученного приблизительного 95% интервала выше нуля, улучшение устойчиво к такой перевыборке на наших данных. Это не гарантия качества на бенчмарке: другой состав запросов и неполная разметка остаются ограничениями.
