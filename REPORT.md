# Отчёт о решении

## Данные и схема

| Данные | Объём | Роль |
|---|---:|---|
| `train.parquet` | 497 673 пар | Известные выборы объявления по запросу |
| `benchmark_items.parquet` | 189 212 объявлений | Корпус для поиска и признаки кандидатов |
| `benchmark_queries.parquet` | 2452 запроса | Запросы для итогового ответа |

Для каждого запроса возвращается до 50 `item_id`. Метрика Recall@50 усредняет долю найденных выбранных объявлений по запросам. Порядок внутри ответа не влияет на балл.

## Что реализовано

1. **Подготовка текста:** нижний регистр, замена `ё` на `е`, удаление пунктуации. Заголовок, параметры и первые 1500 символов описания образуют текст объявления.
2. **Поиск кандидатов:** TF-IDF по словам и символьным фрагментам длиной 3–5. Для каждого индекса берутся глобальный и локальный топ-100. Локация служит дополнительным каналом, а не жёстким фильтром.
3. **BM25:** глобальный и локальный топ-100 добавляются к найденным кандидатам. Параметры: `k1=1.2`, `b=0.75`.
4. **Отбор:** `HistGradientBoostingClassifier` сортирует общий список по 18 признакам — текстовое сходство, локация, категория, фильтры, цена, рейтинг, отзывы и доступность связи. `query_id` и `item_id` в модель не подаются.

Из train объединяются повторные выборы одного объявления при одинаковых условиях поиска. Для локальной оценки доступны 18 436 групп, у которых **все известные** выбранные объявления есть в корпусе. Тексты запросов не пересекаются между обучением, dev и test. Финальная модель обучена на 10 000 группах; dev и test содержат по 500.

## Результаты

| Проверка на общих dev и новом test | Dev Recall@50 | Test Recall@50 |
|---|---:|---:|
| Модель на 2500 группах | 0,7880 | 0,7763 |
| Модель на 6000 группах | 0,7880 | 0,7813 |
| Модель на 10 000 группах | 0,7900 | 0,7943 |
| Та же модель + кандидаты BM25 | **0,7920** | **0,7983** |

Модель на 10 000 группах выбрана по dev. На новом test её преимущество над старой моделью — **1,8 процентного пункта**; парный bootstrap-интервал 95%: **[0,4; 3,37] пункта**. BM25 добавил ещё 0,2 пункта на dev и 0,4 на test. Полнота расширенного списка на test выросла с **0,8433 до 0,8593**.

| Отправка на платформу | Recall@50 |
|---|---:|
| Первая версия | 0,717977 |
| Финальная версия с BM25 | **0,728630** |

**Вывод:** новая версия улучшила внешний балл на **1,0653 процентного пункта**. Локальные оценки выше платформенной: они не дают точного прогноза для скрытой выборки.

## Ошибки и ограничения

| Наблюдение | Последствие |
|---|---|
| В корпусе есть лишь малая часть объявлений, выбранных в train | Локальная проверка проводится на смещённой выборке |
| Некоторые подходящие объявления не попадают в общий список | Отбор не может их вернуть; потолок списка с BM25 на test — 0,8593 |
| Некоторые найденные объявления не проходят в финальные 50 | Есть запас для улучшения модели отбора |
| Невыбранный кандидат считается отрицательным примером | Метки шумные: пользователь мог не увидеть объявление |
| BM25 дал небольшой прирост локально | Нельзя приписывать ему весь прирост платформенного балла без отдельной отправки модели на 10 000 группах без BM25 |

`answer.csv` проверен по всем запросам и идентификаторам корпуса: 2452 строки, по 50 уникальных объявлений, две колонки. Полный повторный запуск из исходных Parquet создал побайтно тот же ответ. Используются локальные open-source библиотеки NumPy, pandas, SciPy, scikit-learn, PyArrow, joblib, Jupyter и threadpoolctl. Хардкода ответов по `query_id` и внешних API нет.
