# Кандидатогенерация для Авито

Основной файл — `solution.ipynb`. Реализованы загрузка данных, первичный анализ, очистка текста, базовый поиск TF-IDF, локальная оценка Recall@50 и проверка/сохранение `answer.csv`. Код разделён на короткие ячейки с пояснениями.

## Запуск

Нужен Python 3.12. В терминале из папки проекта:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m jupyterlab solution.ipynb
```

Если команда `python` указывает на неработающий `WindowsApps/python.exe`, используйте полный путь к установленному Python. На текущем компьютере окружение создано так:

```powershell
& 'C:\Users\pc\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m venv .venv
```

После создания окружения системная команда `python` больше не нужна:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyterlab solution.ipynb
```

Активация окружения не требуется. Путь к встроенному Python Codex относится только к текущему компьютеру; на другом компьютере используйте свой установленный Python 3.12.

Запускайте Jupyter из корня проекта. Ноутбук читает файлы по относительным путям без `pathlib`:

```text
Avito/
  data/
    train.parquet
    benchmark_queries.parquet
    benchmark_items.parquet
  solution.ipynb
  requirements.txt
  README.md
```

Выполните ячейки сверху вниз. При клонировании репозитория положите датасет в `data/` самостоятельно: большие файлы данных исключены из Git.

## Базовое решение

TF-IDF из scikit-learn строится по заголовкам, параметрам и первым 1500 символам описаний объявлений. Заголовок повторяется дважды. Для каждого запроса выбираются до 50 объявлений с положительным косинусным сходством. Категория и география пока не влияют на поиск. Внешние API и скачиваемые модели не используются.

Для экономии памяти train загружается только с пятью признаками запроса и item_id. Контрольные запросы группируются по всем пяти признакам. Для оценки берутся до 500 случайных групп (seed 42), у которых все известные выбранные объявления есть в корпусе. Эта выборка ограничена пересечением train и benchmark_items, поэтому её оценка не является прогнозом результата платформы. Положительные пары не используются для обучения TF-IDF.

Запуск всех ячеек создаёт `answer.csv` в корне проекта. Перед повторным запуском перезапустите ядро Jupyter, чтобы освободить память предыдущего запуска. Файл `baseline_metrics.json` хранит результат проверочного запуска разработчика.

Проверочный запуск: Recall@50 = **0.226524** на 500 группах. Из 354 463 групп обучения 18 436 имеют все известные положительные объявления в корпусе и подходят для этой проверки. Ответ сформирован для всех 2 452 запросов; у 18 запросов нет положительных текстовых совпадений, их ответы пустые. Проверены названия колонок, набор запросов, отсутствие повторов, лимит 50 и принадлежность всех item_id корпусу. Это базовый результат, а не оценка на скрытой разметке платформы.

## Дальнейшая работа

1. Изучить ошибки базового поиска.
2. Проверить обработку форм слов и поиск BM25.
3. Сравнить влияние категории, локации и фильтров на той же контрольной выборке.
4. При обучении на положительных парах отделить контрольные группы от обучения.

Данные и результаты поиска в Git не загружаются. Обработка выполняется локально. Основные зависимости перечислены в requirements.txt; точные версии проверенного окружения — в requirements-lock.txt.

Для установки точных версий используйте `.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt`.
