# Отчёт о решении

## Задача и данные

Для каждого запроса требуется выбрать до 50 объявлений. Метрика Recall@50 усредняет по запросам долю найденных объявлений из числа выбранных пользователями. Порядок внутри ответа не оценивается.

Доступны 497 673 обучающие пары, корпус из 189 212 объявлений и 2452 запроса бенчмарка. Из train используются условия поиска и item_id выбранного объявления; свойства кандидатов берутся из корпуса. Идентификаторы сохраняются строками.

## Метод

Тексты приводятся к нижнему регистру, «ё» заменяется на «е», удаляются пунктуация и повторяющиеся пробелы. Словарный TF-IDF строится по заголовку, параметрам и первым 1500 символам описания. Заголовок повторён дважды для увеличения веса. Параметры индекса: min_df=2, max_features=100000, sublinear_tf=True, float32.

Символьный TF-IDF использует заголовок и параметры, char_wb, фрагменты длиной 3–5 символов, min_df=3, max_features=150000. Он учитывает близкие формы слов и некоторые опечатки. Оба индекса нормируются по L2; оценки — косинусные сходства.

Для каждого запроса объединяются четыре списка по 100 результатов: словарный и символьный поиск по всему корпусу и отдельно в указанной локации. Повторы удаляются, остаётся до 400 кандидатов. Жёсткого ограничения локации нет: в обучающей части она совпадает только у 80,58% известных выбранных объявлений. Пакеты по 32 запроса ограничивают память.

Итоговый отбор выполняется HistGradientBoostingClassifier. Модель использует 18 признаков: два сходства, их сумму и произведение, совпадения локации и категории, наличие категории, длину запроса, доставку, совпадение слов фильтра с параметрами, рейтинг и пропуск, логарифм числа отзывов и пропуск, логарифм цены и пропуск, доступность телефона и сообщений. query_id и item_id признаками не являются.

Параметры бустинга: max_iter=120, max_leaf_nodes=15, learning_rate=0.08, min_samples_leaf=30, l2_regularization=1.0, early_stopping=False. Раннюю остановку отключили, чтобы избежать случайного внутреннего разделения пар одного запроса. Оценки класса 1 служат для сортировки, а не трактуются как откалиброванные вероятности пользовательского выбора.

## Обучение и проверка

Обучающие пары объединены по пяти условиям запроса, повторные item_id удалены. Из 354 463 групп для 18 436 все известные ответы есть в корпусе; только они используются в локальном эксперименте. Около 6,63% исходных строк train относятся к объявлениям корпуса. Это существенное ограничение репрезентативности локальной проверки.

Группы разделены по очищенному тексту: одна формулировка не пересекается между train, dev и test. После разделения выбраны 2500/500/500 групп соответственно. Бустинг обучается только на train, метод выбирается по dev, test используется для окончательной оценки. После просмотра test настройки не менялись; модель для бенчмарка не переобучалась на контрольных ответах.

Известные выбранные кандидаты получают метку 1, остальные — условную метку 0. На запрос сохраняются все найденные положительные и до 80 отрицательных примеров. Суммарные веса классов внутри запроса одинаковы. Невыбранное объявление не обязательно нерелевантно: логов показов нет.

Получено 176 650 обучающих пар, из них 2250 положительных. 320 запросов не дали пары обоих классов и пропущены при обучении отбора. При оценке качества запросы без найденных ответов остаются и получают ноль.

## Результаты

| Метод | Dev Recall@50 |
|---|---:|
| Словарный TF-IDF | 0,2940 |
| Слова + части слов, вес локации 0 | 0,2930 |
| Слова + части слов, вес локации 0,5 | 0,5490 |
| Слова + части слов, вес локации 1 | 0,6907 |
| Слова + части слов, вес локации 2 | 0,7560 |
| Градиентный бустинг | **0,7880** |

Вес локации задаёт множитель 1 + вес для совпадающей локации. Лучшим на dev оказался бустинг. Его результат на независимом test — **0,7445**, у базового TF-IDF — **0,2595**: прирост **48,5 процентного пункта**. Приблизительный 95% bootstrap-интервал разницы — [0,4341; 0,5362], 2000 перевыборок с группировкой по тексту.

**Результат отправки на платформу: Recall@50 = 0,717977.** Он ниже локального test на 2,6523 процентного пункта. Это внешняя оценка текущего answer.csv; она не использовалась для подбора параметров этого решения.

Сложение двух текстовых сходств само по себе не улучшило baseline на dev. Существенный прирост связан с учётом локации. Бустинг добавил 3,2 процентного пункта к лучшей проверенной эвристике на dev. Для изолированной оценки вклада символьного индекса необходим дополнительный эксперимент при одинаковом отборе.

## Ошибки и ограничения

Полнота расширенного списка на test — 0,83. Для 371 из 500 запросов найдены все известные ответы. У 85 запросов правильных объявлений нет среди кандидатов; у 44 они доступны, но не все попадают в финальные 50. Поэтому улучшения возможны на обоих этапах, а один только отбор не может превысить полноту списка кандидатов.

Примеры ошибок поиска: «блокировка айфона» — объявление с общим заголовком о ремонте устройств Apple; «вспашка минитрактором» — объявление о выравнивании участка. Различия формулировок показывают ограничение лексического поиска, хотя не доказывают единственную причину конкретной ошибки. Пример ошибки отбора: «фотостудия без фотографа» — выбранное объявление об аренде фотостудии присутствовало среди кандидатов, но не прошло в топ-50.

Локальная выборка смещена из-за ограничения пересечением с корпусом. В бенчмарке 222 запроса имеют категорию 0, в train таких строк всего 34. Обучение ограничено 2500 группами; оптимальность этого объёма не утверждается. Временных меток для временного разделения нет. Bootstrap-интервал не учитывает сдвиг распределения платформы.

## Воспроизводимость и сдача

Полный проверочный расчёт занял 2117,5 секунды, около 35,3 минуты. Это время всего конвейера, не отдельного обучения бустинга. Производственная задержка поиска не измерялась. Последующие изменения оформления и комментариев не меняют исполняемый алгоритм.

answer.csv содержит 2452 строки с двумя колонками query_id и answer, по 50 уникальных item_id из корпуса. Проверяются идентификаторы, набор запросов, лимит, повторы и обратное чтение CSV. Исходные данные не включены в архив; инструкция запуска находится в README.md.

Использованы открытые библиотеки NumPy, pandas, PyArrow, SciPy, scikit-learn, Jupyter, joblib и threadpoolctl. TF-IDF, символьные n-граммы, градиентный бустинг и bootstrap — стандартные методы. Обработка данных, признаки, объединение кандидатов и схема проверки реализованы в проекте. Выполнение локальное, без внешних API и хардкода ответов под query_id.
