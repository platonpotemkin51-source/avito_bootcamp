# План эксперимента

Цель — повысить Recall@50 относительно поиска по словам и подготовить воспроизводимый `answer.csv`. Все алгоритмы работают локально на CPU. Основной код и пояснения находятся в `solution.ipynb`; `baseline.ipynb` сохраняет предыдущую версию.

## Подготовка и проверка

Из train объединяем пары с одинаковыми пятью условиями поиска. Для локального эксперимента оставляем группы, у которых все известные выбранные объявления есть в корпусе. Это ограниченная выборка: она не отражает весь train и не гарантирует совпадения распределения со скрытым бенчмарком.

Разделяем группы по очищенному тексту запроса: один текст не встречается одновременно в обучении, dev и test. После разделения берём до 2500/500/500 групп соответственно. TF-IDF обучается на текстах доступного корпуса, а модель отбора — только на метках обучающей части.

## Методы

1. Базовый TF-IDF по словам в заголовке, параметрах и первых 1500 символах описания.
2. Символьный TF-IDF по заголовку и параметрам, фрагменты длиной 3–5 символов.
3. Объединение глобальных и локальных списков: до 100 кандидатов из каждого из четырёх каналов, до 400 уникальных кандидатов.
4. Эвристический отбор по сумме двух сходств и множителю совпадения локации. На dev сравниваем множители 1, 1.5, 2 и 3.
5. HistGradientBoostingClassifier на текстовых оценках и свойствах пары. До 80 условно отрицательных кандидатов на обучающий запрос, все найденные положительные, равный суммарный вес двух классов внутри запроса. Модель не получает идентификаторы запросов или объявлений.

## Выбор и отчёт

Метод выбирается по dev Recall@50. Затем сравнивается с базовым на test без последующего подбора по test. Показываем полноту расширенного списка и приблизительный bootstrap-интервал разницы, группируя перевыборку по текстам запросов.

Сохраняем таблицу сравнения, примеры ошибок, метрики и обученную модель. Формируем answer.csv выбранным на dev методом и проверяем формат, допустимые ID и лимит кандидатов. Модель после проверки не переобучаем: итоговый ответ использует ту же версию, которая оценена на test.

## Критерий завершения

Ноутбук полностью выполняется с чистого ядра, содержит фактические результаты и объясняет их ограничения. Итоговый CSV содержит ровно все запросы benchmark_queries, до 50 уникальных item_id из корпуса на запрос. Документация описывает зависимости, запуск и все использованные готовые методы.
