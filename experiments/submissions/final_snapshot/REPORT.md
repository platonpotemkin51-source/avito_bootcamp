# Отчёт: поиск объявлений услуг

## Задача и данные

Для каждого из 2452 запросов нужно выбрать не более 50 объявлений из корпуса 189 212 услуг. Качество измеряется Recall@50: долей выбранных пользователями объявлений, попавших в список кандидатов. Обучающий файл содержит 497 673 пар «запрос — выбранное объявление».

Пять полей `search_*` определяют условия запроса. В локальной проверке одинаковые условия объединяются, а повторный выбор одного `item_id` учитывается один раз. Признаки объявлений для кандидатов берутся из `benchmark_items.parquet`. Идентификаторы всюду остаются строками.

## Поиск кандидатов

Текст очищается: нижний регистр, `ё` заменяется на `е`, пунктуация и лишние пробелы удаляются. Словарный TF-IDF строится по заголовку, параметрам и первым 1500 символам описания; заголовок повторяется для большего веса. Второй TF-IDF использует символьные фрагменты длиной 3–5 из заголовка и параметров. Оба индекса строятся только по корпусу объявлений, без меток выбора.

Для каждого запроса берутся до 100 результатов из каждого из четырёх каналов: словарный и символьный поиск по всему корпусу и в локации запроса. После удаления повторов получается расширенный список до 400 объявлений. Локация не служит жёстким фильтром: часть выбранных услуг находится за её пределами.

Отдельно проверен BM25 со стандартной формулой, параметрами `k1=1.2`, `b=0.75` и тем же словарём, что у словарного TF-IDF. Его глобальные и локальные топ-100 добавляются в расширенный список. Этот вариант оценивается отдельно, чтобы не смешивать прирост поиска с работой модели отбора.

## Отбор и локальная проверка

В финальные 50 кандидатов отбирает `HistGradientBoostingClassifier` из scikit-learn. Он использует 18 признаков: два текстовых сходства и их сочетания, совпадения локации и категории, длину запроса, наличие доставки, совпадение слов фильтра с параметрами, цену, рейтинг, число отзывов и доступность связи. `query_id` и `item_id` в признаки не входят. Параметры модели: 120 итераций, до 15 листьев, `learning_rate=0.08`, `min_samples_leaf=30`, `l2_regularization=1.0`, без случайной внутренней ранней остановки. Модель обучается на известных выбранных объявлениях и найденных невыбранных кандидатах; всего получено 700 716 обучающих пар. Последние являются условными отрицательными примерами: отсутствие выбора не доказывает нерелевантность.

Для оценки оставлены только группы, у которых **все известные** выбранные объявления есть в корпусе: 18 436 групп из 354 463. Тексты запросов разделены между train, dev и test с помощью `GroupShuffleSplit`; одна очищенная формулировка не попадает одновременно в разные части. Используются 10 000 групп для обучения, 500 для выбора метода и 500 для контрольной оценки. Такое пересечение с корпусом делает локальную выборку смещённой относительно платформенного бенчмарка.

| Метод на одинаковых запросах | Dev Recall@50 | Новый test Recall@50 |
|---|---:|---:|
| Отправленная модель, 2500 групп | 0,7880 | 0,7763 |
| Модель на 6000 группах | 0,7880 | 0,7813 |
| Модель на 10 000 группах | **0,7900** | **0,7943** |
| Модель на 10 000 группах с кандидатами BM25 | **0,7920** | **0,7983** |

По заранее заданному правилу модель на 10 000 группах выбрана по dev. Её прирост к отправленной модели на новом test составляет 1,8 процентного пункта; парный bootstrap-интервал 95%: [0,40; 3,37] процентного пункта. Добавление BM25 даёт ещё 0,2 пункта на dev и 0,4 пункта на test. Это небольшой прирост: его устойчивость на скрытом бенчмарке не установлена. Полнота расширенного списка на новом test выросла с 0,8433 до 0,8593 после BM25. Порядок в ответе метрикой не учитывается.

Отправленный финальный файл `submission_final/answer.csv` получил на платформе Recall@50 = **0,728630**; пользователь подтвердил, что загружал именно его. Предыдущий файл получил **0,717977**. Прирост составляет **1,0653 процентного пункта**. Локальные оценки выше платформенных, поэтому их нельзя выдавать за результат скрытого бенчмарка.

## Воспроизводимость и ограничения

Расчёт выполняется локально на Python без внешних API и без ответов, привязанных к конкретным `query_id`. Основные библиотеки: pandas, NumPy, SciPy, scikit-learn, PyArrow, joblib, Jupyter и threadpoolctl. `solution_final.ipynb` выполняет полный расчёт модели на 10 000 группах из исходных Parquet. Отдельные скрипты `bm25_experiment.py` и `predict_bm25.py` документируют эксперимент и формирование варианта с BM25. `validate_answer.py` сверяет CSV с запросами и корпусом. Полный повторный запуск из исходных Parquet дал побайтно тот же ответ с BM25, что находится в комплекте сдачи.

Корпус известен целиком, но большая часть выбранных объявлений из train в него не входит. Разметки показов и всех потенциально подходящих услуг нет. Test применён для оценки, а не для подбора параметров. Производственная задержка поиска не измерялась.
