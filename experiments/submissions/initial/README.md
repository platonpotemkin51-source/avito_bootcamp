# Поиск объявлений услуг

Решение задачи кандидатогенерации: до 50 item_id для каждого запроса. Используются словарный и символьный TF-IDF, поиск по всему корпусу и внутри локации, затем отбор градиентным бустингом.

**Recall@50 на платформе: 0,717977.** Локальный test: 0,7445 против 0,2595 у базового поиска. Схема проверки и ограничения описаны в REPORT.md.

## Состав

- `solution.ipynb` — основной код с краткими пояснениями и сохранёнными результатами.
- `REPORT.md` — метод, эксперимент и выводы.
- `answer.csv` — файл для отправки: 2452 строки, по 50 объявлений.
- `requirements.txt` — зафиксированные версии основных зависимостей.
- `run_notebook.py` — запуск ноутбука из терминала.
- `results/` — метрики, сравнение методов и обученная модель.

## Воспроизведение

Python 3.12. Исходные данные в архив не включены. Создать папку `data` рядом с ноутбуком и положить в неё `train.parquet`, `benchmark_items.parquet`, `benchmark_queries.parquet`.

```bash
python -m venv .venv
```

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 run_notebook.py
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run_notebook.py
```

Альтернатива: открыть solution.ipynb в Jupyter и выполнить все ячейки с чистого ядра. Запускать из каталога проекта. Расчёт выполняется локально на CPU, требует нескольких гигабайт памяти и в проверочном запуске занял около 35 минут. Внешние API не используются.

Запуск перезаписывает answer.csv и сохраняет новые метрики и модель в `outputs/`. Каталог `results/` содержит результаты сдаваемой версии. Модель без корпуса и TF-IDF-индексов не является самостоятельным поисковым сервисом.

Случайные операции используют seed 42. Сохранённые результаты получены полным проверочным запуском; последующая редактура пояснений не меняет вычисления. Учебные материалы, промежуточные копии, окружение и исходные данные в комплект сдачи не входят.
